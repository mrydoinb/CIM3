## 1. 建设目标

本项目面向 CIM 3/4 级城市基础设施表达需求，构建“可建模、可校验、可追溯、可扩展”的城市基础设施数据集生产体系。数据集以城市道路为骨架，逐步扩展到公交站、地铁站、地下管线、轨道交通等基础设施要素，形成统一的语义建模、规则生成、三维构建、质量检查与成果发布流程。

项目最终输出面向 BIM/CIM/GIS 联动应用的多层级三维成果，包括：

- CIM3/CIM4 级公共道路、公交站、地铁站、地下管线、轨道交通数据集模型
- OBJ / FBX 三维交换文件
- 语义化中间结果与调试清单
- 支持 Blender 直接检查的单体或分区成果

## 2. 总体思路

技术路线采用“**多源数据输入 + 统一语义标准化 + 规则驱动的程序化建模 + 几何拓扑校正 + 分级成果输出**”的总体框架。

与传统的纯手工建模相比，本方案强调三个核心能力：

1. **语义先行**：先完成道路、站点、管线等要素的分类、等级、关联与约束定义，再生成几何。
2. **规则驱动**：用道路等级、断面模板、连接规则、净距约束、交叉口规则控制模型生成过程。
3. **分层输出**：同一套基础规则同时支持 CIM3 与 CIM4 两级别成果生产，并保留中间语义文件，方便调试和后续扩展。

## 4. 总体技术路线

### 4.1 数据采集与入库

对多源数据进行统一接入，建立基础资源库：

- 统一坐标系与投影基准
- 统一编码体系与主键体系
- 统一字段字典与枚举值
- 统一几何精度、长度单位和高程单位

### 4.2 数据预处理

对原始数据进行标准化清洗，重点处理：

- 坐标转换与几何修复
- 道路中心线去重、断裂修复、方向归一
- 站点和管线要素的空间吸附与拓扑校正
- 属性字段补全、枚举归一、空值修正
- 生成标准化中间层数据

表2对各处理环节进行归纳。

| 处理环节 | 关键任务 | 主要输出 |
| --- | --- | --- |
| 数据采集与入库 | 统一接入多源数据，建立基础资源库 | 原始数据清单、基础资源库 |
| 数据预处理 | 坐标转换、几何修复、属性归一、拓扑校正 | 标准化中间层数据 |
| 语义建模与规则配置 | 分类编码、属性映射、规则库装配 | 语义模型、规则参数集 |
| 程序化几何生成 | 生成道路、站点、管线、通道模型 | 初始三维模型 |
| 几何校正 | 剪裁、拼接、避让、补面、分层 | 修正后的可用模型 |
| 质量校验 | 几何、拓扑、语义、成果检查 | 校验结果、问题清单 |
| 成果输出 | 语义层、几何层、调试层分级发布 | JSON / OBJ / FBX 等成果 |

### 4.3 语义建模与规则配置

建立统一的基础设施语义模型，将每一类对象映射到可计算的规则参数：

- 道路类型：高速、主干、次干、支路、匝道等
- 断面类型：车行道、中央分隔带、设施带、绿化带、人行道
- 站点类型：公交站、地铁站、换乘节点、出入口、附属设施
- 管线类型：给水、排水、燃气、电力、通信、综合管廊
- 通道类型：轨道交通地下通道、人行过街通道、换乘连通通道

规则库建议包含：

- 几何规则：宽度、半径、转角、净距、埋深、标高差
- 拓扑规则：连接关系、交汇关系、穿越关系、叠置关系
- 约束规则：最小间距、最小长度、最大偏移、冲突消解
- 等级规则：CIM3 与 CIM4 的层级差异、精细度差异和输出差异

### 4.3.1 规则配置逻辑

规则配置遵循“基础参数统一、分级参数可切换、局部规则可覆盖”的原则：

- 基础参数：坐标系、单位、命名、颜色、编码、索引规则
- 分级参数：CIM3 / CIM4 对应的构件拆分粒度、细节层次和输出精度
- 局部规则：路口、站点、管线交叉区、地下通道等特殊场景的局部约束

### 4.4 程序化几何生成

以“中心线 + 断面模板 + 连接规则”为主线生成三维对象。

#### 4.4.1 公共道路生成

道路生成分为五步：

1. 中心线语义解析与道路等级识别
2. 横断面模板匹配与宽度计算
3. 线型扫掠生成道路主体面
4. 路口识别、剪裁和拼接
5. 生成人行横道、标线、护栏、绿化、路灯等附属要素

道路生成结果不仅要求视觉完整，还要求断面参数、路口拓扑和附属构件与中心线保持一致，确保后续可直接进入 Blender 预览和二次编辑。

#### 4.4.2 公交站生成

公交站模型应围绕道路边缘和站台区组织：

- 基于道路等级与站台类型确定站台宽度和长度
- 根据道路行车方向和人行空间设置候车区
- 生成站牌、站棚、站台边界、无障碍设施等附属模型
- 与道路主体保持合理净距，避免穿插

公交站生成强调“依路布设、沿线组织、净距控制”三项原则，以保证站台模型与道路边界、行人空间和机动车道之间关系清晰。

#### 4.4.3 地铁站生成

地铁站重点表达地面出入口、附属建筑和地下空间联系：

- 基于站点点位和线路关系定位站体
- 生成站厅、出入口、风亭、无障碍设施等地面要素
- 与道路、人行通道、地下管线建立空间关联
- 在 CIM3/CIM4 中分别控制表达精度和构件复杂度

地铁站在 CIM3 级以出入口、风亭和简化站体表达为主，在 CIM4 级进一步细化附属构件、地下联系和周边组织关系。

#### 4.4.4 地下管线生成

地下管线采用“线要素 + 埋深 + 标高 + 走廊约束”的方式生成：

- 以中心线确定空间走向
- 以埋深和管径控制空间高度
- 以管线类别决定颜色、线型、分层和间距
- 与道路、站点、通道、建筑基础设置避让与穿越约束
- 对交叉口、井位、变径、分支位置进行结构化表达

地下管线生成应重点满足“分层清晰、穿越可控、属性完备、净距可检”的工程要求。

#### 4.4.5 轨道交通数据集生成

轨道交通数据集面向站城一体和轨道交通场景：

- 依据线路、车站、出入口、周边道路及公共空间组织要素关系
- 通过站体、出入口、附属设施、连通路径等参数构建实体
- 与地铁站、公交站、地下管线共同形成轨道交通空间关系网

轨道交通数据集可作为站城一体化的重要组成部分，在模型中应同步表达线路关系、车站位置、出入口位置、附属设施和空间层级。

### 4.5 连接关系与冲突消解

基础设施数据集的关键不只是“建出来”，还要“连得上、放得下、看起来合理”。因此应建立统一的冲突消解机制：

- 道路之间的交叉口识别、断头路识别、端点吸附
- 道路与站点之间的空间避让
- 地下管线与道路、站点、通道之间的穿越和净距校验
- 地上和地下构件之间的高程分层
- 路口区域的局部重构与补面

表3汇总了典型冲突类型及其处理方式。

| 冲突类型 | 典型场景 | 处理方式 |
| --- | --- | --- |
| 道路交叉冲突 | 路口重叠、中心线未对齐、局部穿插 | 端点吸附、局部剪裁、补面拼接 |
| 站点占道冲突 | 站台与车行道或人行道穿插 | 调整站点位置、控制净距、局部重构 |
| 管线穿越冲突 | 管线与道路、站点、通道空间冲突 | 分层布设、埋深修正、穿越约束控制 |
| 地下空间冲突 | 通道与站体、井位、管廊干涉 | 约束求解、局部偏移、构件拆分 |

**表3  典型冲突类型与处理方式**

### 4.6 质量校验

建议建立“几何质量 + 拓扑质量 + 语义质量 + 成果质量”四级校验机制：

- 几何质量：自交、重叠、悬空、断裂、退化面检查
- 拓扑质量：连通性、闭合性、穿越关系、层级关系检查
- 语义质量：分类是否正确、属性是否完整、命名是否规范
- 成果质量：OBJ/FBX 是否可导入，Blender 预览是否正常，是否支持单体调试

建议将校验结果分为“通过、警告、错误”三级，以支持自动化批处理和人工复核并行推进。

### 4.7 成果输出

输出建议分为三层：

1. **语义层成果**：JSON / GeoJSON / CSV 等，保存要素、属性、规则和关联关系
2. **几何层成果**：OBJ / FBX / glTF 等，保存可视化和交换所需模型
3. **调试层成果**：单体路段、单个站点、单条管线、单个路口的独立文件，方便定位问题

### 4.8 技术路线小结

该路线的核心在于把“城市基础设施表达”拆解为可规则化、可批量化、可校验的流程：输入侧强调多源融合，处理侧强调语义与几何同步，生成侧强调规则驱动和分级输出，验证侧强调质量控制和单体调试。这样既能满足 CIM3 的快速交付，也能支撑 CIM4 的精细表达。

## 5. CIM3 / CIM4 分级构建策略

### 5.1 CIM3 级别

CIM3 重点面向基础表达与批量交付，强调：

- 轮廓完整
- 拓扑正确
- 结构清晰
- 模型轻量
- 适合快速浏览和系统集成

### 5.2 CIM4 级别

CIM4 重点面向更高精度与更强语义，强调：

- 构件细化
- 附属设施丰富
- 站点和管线表达更完整
- 可用于更高精度展示、分析和联动应用

### 5.3 分级实现原则

- 同一基础语义模型驱动 CIM3 / CIM4 两套输出
- 通过规则参数控制构件拆分程度、细节层级和模型复杂度
- 保留统一命名和统一编码，便于跨级联动

表4对两级别的主要差异进行概括。

| 对比项 | CIM3 | CIM4 |
| --- | --- | --- |
| 表达目标 | 基础表达、批量交付、快速浏览 | 更高精度、细节表达、联动分析 |
| 模型粒度 | 轮廓级、主体级 | 构件级、附属设施级 |
| 道路表达 | 车行空间、断面轮廓、路口关系 | 细化断面、附属设施、局部构件 |
| 站点表达 | 出入口、站台、简化站体 | 站体细化、附属构件、连通关系 |
| 管线表达 | 线路、类别、埋深、分层 | 细分管类、节点、井位、穿越关系 |
| 输出特点 | 轻量、易加载、适合平台展示 | 更完整、可分析、适合高精度应用 |

## 6. 与现有项目实现的衔接

结合当前仓库的实现，可以把技术路线直接落到以下模块：

- `src/road/rules.py`：负责道路规则、横断面、分类归一、宽度与约束参数
- `src/road/generator.py`：负责道路几何、路口处理、扫掠和局部修补
- `src/city/pipeline.py`：负责全流程编排、数据入库、要素处理与成果输出
- `src/junction/stack_check.py`：负责路口叠压、冲突与堆叠检查
- `src/render/cross_section_svg.py`：负责横断面检查与可视化辅助

这套实现路径已经具备“规则库 + 程序化几何 + 语义中间层 + FBX/OBJ 输出”的完整闭环，非常适合继续扩展到公交站、地铁站、地下管线和地下通道等基础设施对象。
